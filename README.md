# 反「玄学」点名系统

> 基于 **ELO 评分** 与 **PRD 伪随机分布** 的课堂随机抽取公平性模型
> —— 开题课题《反"玄学"点名：基于 ELO 评分与期望管理的课堂随机抽取公平性模型构建》配套原型系统

纯前端静态网页，**零后端、零构建**，可直接托管在 GitHub Pages 上；所有名单与成绩数据只保存在本机浏览器（localStorage），不上传任何服务器。

---

## 一、它解决什么问题

| 现有系统的问题 | 本系统的做法 |
| --- | --- |
| 纯随机 = 独立事件，有人总被点、有人从没被点（"隐形人"） | **算法二 PRD**：未被点名越久，权重越高；并设硬保底，N 次内必被点到 |
| 抽到谁就问什么，难度与能力错位，造成挫败感 | **算法一 ELO**：优先抽取 ELO 与题目难度最接近的学生，势均力敌 |
| 点名是"惩罚导向"，学生被动焦虑 | **积分经济**：答对得分 → 成长等级 → 心愿兑换，转为"激励导向"（可在设置里整体隐藏该标签页） |
| 公平性只能靠感觉 | **数据面板**：基尼系数、标准差、最长空窗，并可一键跑纯随机对照实验 |

## 二、核心算法

**ELO 动态评分**（开题 PPT 中的公式）

```
E  = 1 / (1 + e^((D − R) / RD))      // 学生 R 答对难度为 D 的题的期望概率
R' = R + k · (S − E)                 // S：答对为 1，答错为 0
```

`k` 调整系数（默认 32）、`RD` 基准差值（默认 400），均可在设置页实时调节。

**PRD 伪随机分布**

第 n 次连续未被点名时的命中概率 `P(n) = C · n`。系统按班级人数的名义概率 `p = 1/N` **二分反解常数 C**，使长期平均命中率精确回到 `p`（见 `js/algo.js` 的 `prdConstant`）。抽取时：

```
权重_i = (C · 未被点名次数_i) ^ PRD强度  ×  exp(−(ELO_i − 难度)² / 2σ²) ^ ELO强度
```

两个"强度"滑块都能调到 0——**全调 0 即退化为纯随机**，正好作为对照组，方便做课题里的对照实验。

## 三、快速开始

直接双击 `index.html` 即可在浏览器中使用（无需联网、无需安装）。

跑算法自测：

```bash
node tests/test-algo.mjs
```

## 四、部署到 GitHub Pages

1. 在 GitHub 上新建一个仓库，例如 `elo-rollcall`（Public）。
2. 把本目录所有文件推上去：

```bash
git init && git add -A && git commit -m "ELO 点名系统"
git branch -M main
git remote add origin https://github.com/<你的用户名>/elo-rollcall.git
git push -u origin main
```

3. 仓库页面 → **Settings** → **Pages** → Source 选 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)` → Save。
4. 等 1–2 分钟，访问 `https://<你的用户名>.github.io/elo-rollcall/` 即可。

> 仓库里已包含空文件 `.nojekyll`，避免 GitHub Pages 的 Jekyll 处理干扰静态资源。

## 五、名单跟着仓库走 & 别人如何自己用

**数据分两层**：名单存在仓库里（静态文件，人人可见、可 fork），成绩只存在各自浏览器里（localStorage，互不干扰、不上传）。这样既能"改一次仓库、所有人打开都是新名单"，又不需要任何后端和令牌。

### 让名单跟着仓库走

仓库里的 `data/roster.json` 就是**种子名单**：

```json
{
  "class": "八年级一班",
  "demo": false,
  "students": [
    { "name": "张三", "group": "第一组", "elo": 1280 },
    { "name": "李四", "group": "第一组", "elo": 1150 }
  ]
}
```

- 浏览器**第一次**打开网页（本机还没有存档）时会自动读取它作为初始名单；
- 已经在用的人不会被覆盖——他们的成绩安全，想更新时点「名单 → ⭳ 载入仓库名单」即可（会清空成绩记录，有确认框）；
- 不想手写 JSON：在网页里把名单调好，点「名单 → ⭱ 导出为仓库名单」得到 `roster.json`，上传替换仓库里的 `data/roster.json` 就行；
- `elo` 可省略，省略则统一用设置里的初始分（默认 1200）；`demo: true` 会让右上角标注为虚拟名单。

改完推送后约一分钟，Pages 自动重新发布。

### 别人想用自己的名单？fork 一份自己挂

1. 在仓库页面点 **Fork**（fork 出来的是自己的仓库，和原仓库数据完全隔离）。
2. 直接在 GitHub 网页上编辑 `data/roster.json`，换成自己班的名单并 Commit。
3. 自己仓库的 **Settings → Pages** → Source 选 `Deploy from a branch`、分支 `main`、目录 `/ (root)` → Save。
   （fork 出来的仓库 Pages 默认是关的，必须手动开一次。）
4. 一两分钟后访问 `https://<对方用户名>.github.io/elo-rollcall/`。

嫌麻烦的话，其实**不 fork 也能用**：直接打开原网址，点「导入 Excel 名单」换成自己的名单即可——名单只存在他自己的浏览器里，不会影响别人看到的版本。

> 想做多设备实时同步（比如手机和教室电脑共用一份成绩）就需要后端数据库了，那意味着学生姓名与答题记录要离开本机；本项目刻意不做这件事。跨设备迁移请用「设置 → 导出/导入存档 (JSON)」。

## 六、导入真实名单

系统默认装载 **30 人虚拟名单**用于演示。换成真实名单：

「名单」页 → **导入 Excel 名单** → 选择 `.xlsx / .xls / .csv`（也可直接把文件拖到网页上）。
弹窗中可指定 **姓名列 / 组别列 / 参考成绩列**，系统会自动猜测。若选了成绩列，会按班级平均分与标准差把成绩线性映射为初始 ELO（`1200 ± 150×z`，上下限 ±2.5σ）；若表格里填的本身就是 ELO 分（600–2600），则原样使用。点「下载模板」可获得标准格式示例。

导出用「导出数据」，生成含 **名单与统计 / 点名流水 / 心愿兑换记录** 三个工作表的 Excel。
